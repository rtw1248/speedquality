# v1.4.0发布说明

- 第三方节点默认按IP共享1000Mbps预约预算，取消统一3任务上限；同IP不同端口共用额度。
- 候选先按IP去重，分批检查质量与容量，并优先分配占用较低的节点；满载时继续尝试其他候选。
- 自建节点新增“用于SQ的总带宽”设置，配合单任务最高档位自动计算可分配任务；默认1000Mbps与200Mbps。
- 平台和节点本地分别原子检查预算；同节点IPv4/IPv6、公共与Route Key任务共享预算，完成或到期后释放。
- 安装摘要、管理菜单、状态和运行统计展示总预算及已预约带宽，任务数用于观察。
- 老节点自动更新程序后保留原容量策略，提供者确认`sudo sq-node limit bandwidth 1000`或在菜单确认后才切换。
  旧自用保留位置改为Route Key优先调度，迁移时会说明差异；已有流量额度和凭据保留。

## 发布顺序

先备份Core数据库，应用`0007_bandwidth_capacity.sql`，部署Core 0.3.0及1000Mbps默认配置；
再发布签名的sq-node二进制并更新公共入口。已有任务可以自然结束，旧节点继续兼容。

## 验证范围

验证混合档位、并发原子预约、双栈与公共/自用共享、超额等待与释放、重复请求、到期恢复、
旧配置迁移、数据库迁移回滚、HTTP与临时网关容量保护，以及Cloudflare/VPS两种数据库适配。
合成测试验证调度正确性；第三方真实空闲带宽和公网高负载表现仍需上线后观察。
