# 社区节点安全与隐私需求 v1

本文定义 SpeedQuality 社区节点进入公开调度前必须满足的主机隔离、防滥用、运行数据和隐私
要求。第一版代码已经实现主要阻断和隔离动作，真实 Linux 发行版、云安全组、nftables 双栈与
公网压力仍需部署验收。逐项状态以 [`roadmap.md`](roadmap.md) 为准。

第一版遵循“功能和行动优先”：只开发能够直接阻止请求、限制损失、隔离节点或恢复服务的能力。
攻击来源收集、跨节点画像、趋势分析和主动预警全部暂缓，不阻塞 Alpha 或 Beta 发布。

## 1. 安全目标与边界

社区节点直接接收测速用户的上传和下载流量。安全设计必须做到：

- 测速服务被滥用或攻破时，尽量不能读取、修改节点上的其它服务和用户数据。
- 未取得有效租约的来源不能长期占用测速连接、CPU、内存或磁盘。
- 每次测速受来源 IP、节点、端口、速度、字节数、并发和时间共同约束。
- 第一阶段只上报运行所需的健康、容量和总流量，不采集跨节点攻击画像。
- 节点提供者能够查看上报内容、退出公共调度并选择完全自建。
- 安装和卸载不修改用户 SSH 配置，不删除用户软件、文件或系统库。

以下情况不作技术保证：

- 已经取得合法租约的用户最终可以从操作系统网络状态中观察本次节点地址。
- 节点本地防火墙无法阻止已经打满服务商公网入口的流量攻击。
- IP、会话和租约只能关联到来源服务器，不能据此确认现实中的个人身份。

因此节点地址不得被当作安全凭据，社区节点也不应和数据库、钱包、生产网站等重要业务共用
公网 IP 或服务器。

## 2. 威胁模型

系统需要处理以下来源：

| 来源 | 典型行为 |
| --- | --- |
| 普通互联网扫描 | 扫描 IPv4、SSH 和高位 TCP 端口 |
| 恶意测速用户 | 申请合法租约后记录地址、占用并发或泄露节点 |
| 被控制的用户服务器 | 使用合法会话发送异常流量，用户本人可能不知情 |
| 外部攻击网络 | 得到节点 IP 后从大量地址发起连接或带宽攻击 |
| 恶意节点提供者 | 虚报地区、运营商、容量或测速结果 |
| 凭据泄露 | Route Key、API Token、发布密钥或平台密钥被窃取 |

重点保护的资产包括节点主机文件、SSH 管理入口、节点凭据、带宽额度、平台节点目录、报告可信度
以及测速用户来源 IP。

## 3. 节点运行模式

| 模式 | 调度范围 | 平台数据 |
| --- | --- | --- |
| `public` | 参加公共调度，也允许 Route Key | 注册、健康、容量和总流量心跳 |
| `private` | 只允许 Route Key | 只需注册、健康和容量心跳，攻击明细可只留本机 |
| `paused` | 不接受新任务 | 只保留最低限度注册心跳，或由提供者直接注销 |
| 完全自建 | 只连接自有 Worker/Core | 不向 SpeedQuality 官方平台发送数据 |

首次配置仍以 `public` 作为产品默认选项，但启用前必须完成安全预检并明确展示上报内容。发现
严重风险时自动保存为 `private`，由提供者修复后手动执行 `sq-node access public`。严重风险包括：

- SSH 允许公网密码登录或 root 密码登录。
- 节点服务只能以不受约束的 root 进程运行。
- 系统没有可用的动态防火墙能力。
- 测速端口与已监听的管理端口冲突。

无法从主机内部判断云安全组状态时必须提示人工核对，不能假定其已经安全。

## 4. 一次性防火墙租约

公开节点使用出站控制通道接收租约准备指令。平台只有在节点确认临时规则已经生效后，才把测速
租约交给用户。

```text
用户服务器     Worker        Core          节点网关      nftables
    │             │             │              │             │
    │ 申请租约    │             │              │             │
    ├────────────▶├────────────▶│              │             │
    │◀─ 202 ──────┤◀────────────┤              │             │
    │             │◀───────────────────────────┤ 认证轮询    │
    │             ├────────────▶│              │             │
    │             │◀────────────┤ 待确认命令   │             │
    │             ├───────────────────────────▶│             │
    │             │             │              ├────────────▶│ 加规则
    │             │◀───────────────────────────┤ ACK         │
    │             ├────────────▶│              │             │
    │ 再次申请    │             │              │             │
    ├────────────▶├────────────▶│              │             │
    │◀─ 已就绪 ───┤◀────────────┤              │             │
    │ ════════════════════════════════════════▶│ 随机端口    │
    │             │             │              ├────────────▶│ 超时删除
```

具体要求：

- 节点通过带 API Token 的出站短轮询取得控制指令，不向平台开放 SSH 或远程 Shell。
- 每个租约分配 `50000-59999` 范围内的随机外部端口，并映射到节点内部固定测速端口。
- 防火墙规则同时绑定来源 IPv4/IPv6、外部端口、协议和 TTL；默认 3 分钟，协议硬上限 15 分钟。
- 规则写入成功并返回 ACK 后，Worker 才能向探针返回租约。
- 释放、撤销、超时或节点暂停时删除规则；控制通道中断时停止确认新租约，现有规则由 TTL 清理，
  进程崩溃后也由 nftables timeout 自动清理。
- 节点地址不进入网页、报告、普通日志或 Bash 变量，只在 `sqprobe` 进程内短暂使用。
- 租约 JWT 继续绑定来源 IP、Node ID、档位、单方向字节上限、过期时间和一次性 `jti`。
- 地址混淆只用于减少无意泄露和批量收集，不能宣称能对已测速用户隐藏真实地址。

防火墙网关是独立 systemd 单元，以 `speedquality` 用户和 `CAP_NET_ADMIN` 运行，只管理
SpeedQuality 自己的 nftables table/chain：

- 只接受合法 IP、允许的端口范围和受限 TTL。
- 拒绝 SSH 端口、当前检测到的管理端口以及任意命令字符串。
- 不能执行 `flush ruleset`，不能修改系统现有 chain、默认策略或云安全组。
- 租约打开、关闭、失败和控制通道异常写入不包含地址、端口或凭据的结构化日志。
- 公共模式下辅助程序失败必须关闭新租约，不能退化为无防火墙公开运行。
- 网关只做来源校验和原始 TCP 转发；外部 HTTP 由无 capability 的低权限主服务解析。

## 5. SSH 与主机安全检查

第一版安装器和 `sq-node preflight` 只读检查以下内容：

- `sshd -T` 的 `PasswordAuthentication`、`PermitRootLogin`、`PubkeyAuthentication` 和
  `MaxAuthTries` 有效值。
- 系统是否存在且可读取 nftables 规则，以及内部测速端口是否在保留范围。
- 主机是否同时监听常见数据库、面板或其它高风险管理端口。

云安全组、SSH 来源范围、发行版安全更新以及已有 IPv4/IPv6 防火墙策略无法由当前版本可靠
归一判断，安装摘要会要求提供者人工核对。部署验收会按发行版补充确定性的检查；在此之前不把
“找到 nftables”描述为整台主机已经安全。

程序不得自动编辑 `sshd_config`、重启 SSH、修改用户密钥或关闭管理端口。检查结果分为：

| 等级 | 行为 |
| --- | --- |
| 通过 | 允许确认后进入公共调度 |
| 警告 | 展示风险和修复建议，允许提供者明确确认 |
| 严重 | 强制保留 `private`，修复后重新检查并手动公开 |

推荐的节点管理路径是 WireGuard、Tailscale、Cloudflare Tunnel 或服务商控制台。必须公开 SSH 时，
应使用密钥登录、禁用 root 和密码登录，并在云安全组或防火墙中限制管理来源 IP。更改 SSH 端口
只能减少扫描噪声，不能作为安全措施。

## 6. sq-node 权限隔离

公开版本必须把常驻测速进程从 root 分离：

- 创建无登录 Shell 的 `speedquality` 系统用户和专用用户组。
- 配置与运行状态迁移到专用目录，权限限制为该用户和必要的管理命令可读写。
- 常驻服务不能读取 `/root`、用户 Home、SSH 密钥、数据库目录或其它业务配置。
- systemd 至少设置 `NoNewPrivileges`、`ProtectSystem=strict`、`ProtectHome=true`、
  `PrivateTmp=true`、`PrivateDevices=true` 和空的 `CapabilityBoundingSet`。
- 限制可用地址族、最大内存、任务数、文件描述符和重启频率。
- HTTP 请求设置头部、正文、空闲、读写和总时长上限。
- 常驻服务不根据网络输入执行 Shell、systemd、包管理器或任意本地命令。
- 签名更新器与测速服务分离；只有受限的一次性更新单元使用 root，且只接受 Ed25519 签名清单
  中的固定目标文件。
- 网关读取本机配置，但只使用 API Token 认证控制轮询并派生本机 HMAC，不解析或记录 Route Key
  和测速 JWT，也不把 API Token 写入命令行或日志；测速 JWT 只由低权限主服务处理。

systemd 限制需要在 Ubuntu、Debian、AlmaLinux 和 Rocky Linux 的受支持版本上实测，兼容性不明的
限制不能静默跳过，应让节点保持 `private` 并显示原因。

## 7. 应用层资源限制

除防火墙外，节点进程自身仍需执行：

- JWT 校验前的单来源连接与请求令牌桶。
- 整个监听服务的连接、等待请求和 goroutine 硬上限。
- 激活、上传、下载和释放分别设置并发与速率限制。
- 公共任务、Route Key 任务和两者合计的每日硬流量上限。
- 单方向最大字节数、任务总时长、空闲连接时间和一次性 JWT 防重放。
- Route Key 独立轮换和撤销，不要求注销整个节点。
- 匿名 `/healthz` 只返回存活状态和协议版本；容量和流量通过认证心跳上报。
- 本地状态落盘设置大小上限、原子替换和异常恢复，攻击不能无限增长日志或状态文件。

本地限制必须先于平台反馈生效；Core 或 Worker 暂时不可用时，节点应拒绝新的公共租约并让已有
租约按字节和时间上限自然结束。

## 8. 紧急停止与受攻击处置

节点提供者必须能够用一个命令或终端菜单立即隔离测速服务：

```text
sq-node emergency-stop
```

该操作必须原子完成或保持失败关闭：

- 把平台访问状态持久化为 `paused`，立即退出公共和 Route Key 调度。
- 撤销所有待确认和活跃租约，拒绝尚未使用的 JWT。
- 删除所有临时随机端口和 nftables 租约规则。
- 停止公网数据监听，只保留不接受入站连接的出站控制心跳。
- 重启服务、机器或自动更新后仍保持隔离，不能自动恢复 `public`。
- 不修改 SSH、其它服务、防火墙默认策略或用户文件。

恢复必须由提供者主动执行安全检查并明确确认，不能根据攻击消失或定时器自动恢复。`unregister`
在此基础上继续撤销 Node ID、Route Key 和 API Token。

不同攻击下，关闭节点的效果不同：

| 攻击类型 | 紧急停止后的效果 | 后续处理 |
| --- | --- | --- |
| 合法租约滥用、HTTP 洪泛 | 服务停止响应，应用层资源消耗终止 | 保持隔离并检查日志 |
| 扫描或攻击测速端口 | 端口规则删除，不再进入 `sq-node` | 本机防火墙继续丢弃 |
| SSH 或其它端口攻击 | 不受测速服务停止影响 | 限制 SSH 来源、禁用密码或使用 VPN |
| 针对整个公网 IP 的 DDoS | 可能继续占满公网入口 | 联系服务商清洗、封堵、空路由或更换 IP |
| 怀疑主机已经被入侵 | 停止节点不能恢复可信状态 | 隔离主机、轮换凭据并从可信镜像重建 |

第一版已经提供 `sq-node emergency-stop`。`sq-node access paused` 只拒绝新的激活；需要立即删除
随机端口并停止公网网关时，应使用紧急隔离命令。恢复命令会先执行预检并回到 `private`。

## 9. 第一阶段运行数据与隐私

第一阶段不建设跨节点攻击画像、攻击来源采集或主动预警，只上报平台完成调度所必需的数据：

- Node ID、代理版本、协议能力、访问模式、心跳和准入状态。
- 当前总任务数、公共任务数、可用状态、公共与全部任务总流量及活动预留。
- 最大档位、并发、公共与总额度、可用时间、紧急隔离和临时网关是否就绪。

第一阶段禁止上报：

- 无效请求或防火墙丢弃请求的来源 IP、网段、ASN 和逐次明细。
- SSH、网站、数据库、面板及其它端口的连接、日志和认证结果。
- 整机网卡流量、端口、进程、目标地址或 conntrack 明细。
- 数据包正文、上传内容、下载内容、用户文件、Shell 历史或环境变量。
- Route Key、API Token、JWT、激活 key、SSH 密钥、密码或发布私钥。

平台仍可根据心跳超时、节点主动报告不可用和连续测速失败停止调度，但不能把这些情况展示成已经
确认的攻击。运行数据不得用于广告、用户画像或出售，字段和保留期限必须在节点确认前展示。

第一版提供以下透明度和处置命令：

```text
sq-node telemetry           显示当前认证心跳将上报的完整 JSON
sq-node preflight           重新执行主机安全预检
sq-node status              显示防火墙租约、限制和隔离状态
sq-node route-key rotate    单独轮换 Route Key
sq-node route-key revoke    单独撤销 Route Key
sq-node emergency-stop      立即隔离测速服务
sq-node emergency-stop --recover  预检后恢复为 private
```

## 10. 暂缓的跨节点安全分析

跨节点攻击来源采集和主动预警不作为私有 Alpha 或公开 Beta 的开发门槛。只有在实际攻击数据证明
它能提供明确价值，并重新取得节点提供者同意后，才单独设计、开发和上线。

未来评估时可以研究平台是否能够关联：

- 同一来源摘要是否在短时间命中多个节点。
- 是否集中来自同一网段、ASN、云服务商或代理网络。
- 攻击是否紧跟某次租约，以及是否精确命中该租约独有的随机端口。
- 是单来源高速攻击，还是大量地址组成的低速分布式行为。
- 节点是否出现带宽饱和、连接不释放、持续鉴权失败或异常重启。

未来的处置仍应分级并允许自动衰减：

1. 节点本地立即限速或短时拒绝，不等待中心判断。
2. Worker 暂停为高风险来源签发新会话。
3. 对明确来源实施 10 分钟、1 小时、24 小时的逐级临时封禁。
4. 多节点同时命中或精确命中独有端口时提高风险分数并告警。
5. 节点带宽、连接数或错误率超过安全线时自动暂停公共调度。
6. 人工复核后恢复节点、延长封禁或通知服务商处理。

不能因为少量事件自动永久封禁整个 ASN、国家或共享出口。TCP 完整连接的来源地址可以用于风险
关联，只有 SYN 的来源地址可能被伪造，不能据此认定攻击主体。

在该能力正式启用前，节点不得上传攻击来源 IP、来源 HMAC、其它端口事件或整机网络摘要。

## 11. 界面与告知要求

节点安装摘要必须显示：

```text
访问模式：       public
SSH 安全检查：   通过 / 警告 / 严重
防火墙租约：     可用 / 不可用
服务运行账户：   speedquality
运行状态上报：   健康、容量、可用状态和总流量
攻击来源上报：   关闭（暂缓）
隐私协议版本：   v1
```

确认文案必须说明公共节点会发送哪些运行信息，并提供 `public`、`private` 和退出三个选择。不得用
笼统的“匿名遥测”代替字段清单。

公共覆盖页只显示省份、运营商、IP 类型、可用档位、在线数量区间和汇总容量区间。节点 IP、端口、
Node ID、Route Key、单节点余额及攻击细节只允许经过认证的运营后台访问。

## 12. 验收标准

社区节点公开前至少完成：

- 使用非特权用户运行，验证其无法读取 `/root`、用户 Home 和常见服务配置。
- 防火墙辅助程序的参数模糊测试，证明不能修改 SSH 或 SpeedQuality 之外的规则。
- IPv4/IPv6 临时规则的创建、ACK、释放、超时、进程崩溃和机器重启测试。
- 大量无效 JWT、慢连接、连接不释放和超大正文测试，验证内存、goroutine 和日志有硬上限。
- 合法租约仍能完成 100/200/400 Mbps 测试，防护不能明显破坏测速结果。
- Core、Worker、控制通道或运行状态上报中断时节点保持失败关闭，并能够自动恢复。
- 验证运行状态上报中不存在来源 IP、凭据、用户文件、数据包正文和无关连接。
- 验证 `emergency-stop` 在活跃测速、控制面离线和进程重启时均能保持隔离。
- 验证 Route Key 轮换和撤销不会影响 SSH 或其它系统服务。
- 在 Ubuntu、Debian、AlmaLinux、Rocky Linux 的 `amd64/arm64` 环境验证安装、升级和卸载。
- 使用服务商流量图验证大流量攻击边界，文档不得承诺本机防火墙可以抵御上游带宽饱和。

## 13. 实施顺序

```text
低权限服务与 systemd 隔离
            │
            ▼
```
