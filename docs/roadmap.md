# SpeedQuality 总体需求与发布路线

本文记录已经确定的产品边界、当前实现状态和后续工作。状态含义：

- `[已实现]`：代码和自动化测试已经存在。
- `[待实测]`：代码已经存在，但尚未在正式 Cloudflare 和真实节点环境验收。
- `[未开发]`：已经讨论并确定方向，当前仓库没有完整实现。
- `[暂缓]`：已经记录但不进入当前版本，等待真实运营证明价值后再决定。
- `[外部风险]`：依赖第三方服务、使用规则或真实网络条件，代码本身不能消除。

## 1. 产品定位

SpeedQuality 是面向 Linux VPS 的区域网络评测工具。用户从待测服务器执行一条 Bash 命令，
测试该服务器到指定省级地区和运营商测速节点的应用层单线程吞吐，并取得可分享报告。

核心方向是受控速率、流量保护、地区验证、报告关联和可替换节点网络。项目不宣传为“更准确的
全球网测 CLI”，也不以复刻 Taier、TcpQuality 或 NodeQuality 的页面和文案作为卖点。

## 2. 用户入口与参数

- `[已实现]` 一键入口：`bash <(curl -fsSL https://<域名>/run)`。
- `[已实现]` `-p, --province` 支持代码、中文省级名称和多个地区。
- `[已实现]` 英文逗号、中文逗号和顿号均可作为分隔符。
- `[已实现]` 城市名称不会静默映射；例如“武汉”会提示使用“湖北”或 `hb`。
- `[已实现]` 不传 `-p` 时从 `SSH_CONNECTION`、`SSH_CLIENT` 或登录会话识别来源。
- `[已实现]` 跳板机只能识别最后一跳，终端会允许用户手动覆盖。
- `[已实现]` 境外、内网或无法识别来源时，交互运行要求手动选择，非交互运行停止。
- `[已实现]` `-p all` 关闭；一次最多 5 个省级地区。
- `[已实现]` `-p bsg` 展开为 SSH 来源省份加北京、上海、广东并去重。
- `[已实现]` `-s, --speed` 只接受 `100/200/400 Mbps`，默认 `200 Mbps`。
- `[已实现]` 默认自动测试可用的 IPv4/IPv6；`-v4` 和 `-v6` 分别限定为仅测对应类型。
- `[已实现]` `--nq` 接受 NodeQuality 报告 URL 或 token，没有该参数时生成独立报告。
- `[已实现]` `-l, --list-provinces`、`-h, --help` 和 `--version`。
- `[决策]` 公开版本固定单线程和 5 秒正式测试，不公开 `--mode` 或 `--duration`。
- `[决策]` 暂不支持教育网，只使用电信、联通和移动三类节点。
- `[待确认]` 香港、澳门、台湾当前在地区表中，正式发布前需要根据真实节点覆盖决定是否保留。

## 3. 测速和流量保护

- `[已实现]` Go 探针进行应用层流式上传和下载，不依赖 `iperf3`。
- `[已实现]` 每方向约 2 秒预热和固定 5 秒正式测量。
- `[已实现]` 探针在应用层限制到 100、200 或 400 Mbps。
- `[已实现]` 正式阶段达到档位 98% 时显示 `✓`，没有达到时显示实际速率；颜色阈值为 80% 和 30%。
- `[已实现]` 运行前按地区、三网、IP 类型和档位估算最大流量。
- `[已实现]` 预计流量达到 10 GB 时，交互运行必须确认，非交互运行停止。
- `[已实现]` 测试前后读取默认出口网卡计数器，展示实际接收、发送和合计流量。
- `[已实现]` 电信、联通、移动依次正式测速，避免争抢用户服务器带宽。
- `[待实测]` 与参考客户端在同一节点交替测试，确认中位吞吐差异和目标档位覆盖。
- `[待实测]` 验证低速、高延迟、丢包、IPv6、连接中断和 `429/503` 场景。

## 4. 节点来源和调度

### 全球网测兼容层

- `[已实现]` 私有 Node Core 动态查询节点目录，不在公开仓库内置生产节点 IP。
- `[已实现]` 兼容层把第三方原始协议转换为公开 Worker 使用的通用短期租约。
- `[已实现]` 目录结果按来源、地区、IP 类型和运营商短时缓存。
- `[已实现]` 按物理 IP 原子预留容量，逻辑标签不能绕过总容量限制。
- `[已实现]` 按速度档位记录成功率、延迟和吞吐反馈。
- `[已实现]` 地区目录标签与独立 IP 地理信息冲突时拒绝节点，内部审计不对外展示。
- `[待实测]` 确认中心接口从 Cloudflare 出口查询时，返回节点仍适用于全国用户。
- `[待实测]` 从至少两个不同出口验证各省三网节点的激活、上传、下载和释放。
- `[待实测]` 观察节点级 `429`，据真实数据设置并发、冷却和失败恢复策略。
- `[外部风险]` 上游鉴权、接口、节点、限流和使用规则可以改变。

### SQ 自建节点协议

- `[已实现]` 公开 `POST /activate`、`GET /download`、`POST /upload`、`POST /release` 协议文档。
- `[已实现]` `STATIC_NODES` 支持个人使用自己的节点完成全套测试。
- `[已实现]` Fixture Provider 用于验证动态 Provider 合同，不包含生产节点。
- `[已实现]` 可直接安装的 `sq-node` 服务端程序，发布 Linux `amd64/arm64` 二进制。
- `[已实现]` `/install-node` 一键校验安装，以及 `sq-node setup` 首次配置、注册和 systemd 启动向导。
- `[已实现]` 无参数进入的 Linux 终端编号菜单和快捷子命令。
- `[已实现]` 在 `50000-59999` 中自动选择并持久化服务端口。
- `[已实现]` 安装时分别通过 IPv4/IPv6 自动识别公网地址，并从平台取得地区、ASN 和运营商候选。
- `[已实现]` 正常安装只显示一次摘要；自动识别失败时仅询问缺失的地区或运营商。
- `[已实现]` 节点默认 `100 Mbps`、单并发、每日 `10GB` 公共额度、`20GB` 总额度、公开模式和全天运行。
- `[已实现]` 每日可用时间、IANA 时区和跨午夜时间段，非可用时段拒绝新任务。
- `[待实测]` 在不同国内 ASN、双栈、NAT 和常见云安全组环境验证自动识别与公网可达性提示。

### 社区节点网络

- `[已实现]` 节点注册、一次性所有权挑战、心跳、注销和重新注册凭据。
- `[已实现]` 节点本地 `public/private/paused` 三种访问状态，默认公开并可随时关闭。
- `[已实现]` 每日公共流量、最大速度、总并发和提供者保留并发配置。
- `[已实现]` 公共额度与提供者保留并发分离，公共任务不能耗尽提供者自用位置。
- `[已实现]` 默认单并发节点不长期闲置容量；Route Key 请求遇忙后取得短暂的下一位置优先权。
- `[已实现]` 平台校验来源 IP、地区、IPv4/IPv6 和持续健康状态；有可信 ASN/组织证据时同时
  拒绝冲突的运营商声明，无法识别时保留人工确认与后续运营校验。
- `[已实现]` 节点调用平台使用可撤销 API Token，平台只保存加盐哈希。
- `[已实现]` 平台签发短期 ES256 JWT，绑定节点、来源 IP、速度、字节上限、过期时间和一次性 ID。
- `[已实现]` `--node ROUTE_KEY` 精确使用提供者自己的节点；不可用时直接失败。
- `[已实现]` 普通调度优先 SQ 原生节点，只对缺失运营商使用兼容节点。
- `[已实现]` `LEGACY_FALLBACK_ENABLED=false` 可完全关闭第三方兼容回退。
- `[已实现]` 节点上报程序版本、协议版本、通用能力和当前可用状态，调度按能力过滤。
- `[已实现]` 新节点先进入观察状态，连续认证心跳达到准入次数且临时网关就绪后才参与公共调度；
  Route Key 在网关就绪后可自测。
- `[已实现]` 公共调度使用独立认证档位，节点提供者不能只修改本地配置绕过平台认证。
- `[已实现]` `stable` 签名更新清单、SHA-256 二次校验、systemd 随机定时检查、原子替换和失败回滚。
- `[待实测]` 在公网完成节点注册、双向测速、心跳离线、健康失败、额度耗尽和并发竞争验收。
- `[决策]` 指定节点不传 `-p` 时采用节点验证地区；显式地区不一致时拒绝。
- `[决策]` “节点池”只属于平台内部调度，不向普通用户提供 `--pool` 参数或完整节点清单。

## 5. NodeQuality 关联报告

- `[已实现]` 用户只有显式传入 `--nq` 才会关联报告。
- `[已实现]` 校验当前服务器与 NQ 报告的完整 IP；掩码 IPv4 至少匹配前两段和 ASN。
- `[已实现]` 从多个候选时间中选择最晚有效时间。
- `[已实现]` 两次检测相差不超过 60 分钟时正常展示，超过时在 SQ 页高亮。
- `[已实现]` 服务器不一致或无法验证时拒绝关联，只生成独立 SQ 报告。
- `[已实现]` 安全解压和大小限制可阻止路径穿越、压缩包膨胀及危险控制符注入。
- `[已实现]` NQ 校验由静态 `sqprobe` 完成，不安装 Python、pip、虚拟环境或系统依赖。
- `[已实现]` 联合报告保留 NQ 分页顺序、正文空白和可见 ANSI 样式，最后追加“速度质量”页。
- `[已实现]` NQ 分页不展示 SQ 校验、推广、统计或到期信息；这些只在 SQ 页展示。
- `[已实现]` 联合报告顶部显示 `NodeQuality + SpeedQuality`，独立报告只显示 `SpeedQuality`。
- `[已实现]` 独立 SQ 报告与联合报告共用暗色终端框架，只有一个页面时隐藏分页栏。
- `[已实现]` 每个 NQ/SQ 分页在正文上方和下方各提供一组复制按钮，支持纯文本、NodeSeek tabs
  格式和通用 Markdown；NodeSeek 输出
  使用 NQ 同款 `:::: tabs` / `::: tab-item` 与 `ansi` 代码块，后两种格式同时下载 Markdown
  文件。联合格式包含清洗后的 NQ 内容、图片及原始来源链接，NQ 分页保持不变。
- `[已实现]` 完整 IP 一致、脱敏 IP 网段及 ASN 一致时显示绿色；身份一致但超过 60 分钟或
  时间无法确认时显示橙色；身份不一致或报告无法读取时拒绝联合并在独立 SQ 报告中显示红色原因。
- `[规划]` 只有第二类测量能力正式发布并产生有效结果后，独立报告才增加“连接质量”分页。
- `[已实现]` 页面始终提供 NodeQuality 原始报告链接，不声称官方合作。
- `[待实测]` 使用真实、当前版本的 NQ 报告检查分页、图片、编码、时间和移动端显示。
- `[已实现]` 增加运营侧 NQ 联合报告开关；关闭后 `--nq` 明确提示并回退到独立 SQ 报告，
  不影响普通测速，也不继续抓取或保存新的 NQ 快照。
- `[外部风险]` 当前功能会读取并临时保存经过清洗的 NQ 报告快照。保持原内容和明确来源可以降低
  误解，但不能消除第三方 API、内容再展示和服务变更风险。

## 6. 分享报告和存储

- `[已实现]` 公开 Worker 保存结构化测速结果并生成 `/r/<id>`。
- `[已实现]` D1 保存报告元数据、会话、限流和统计计数。
- `[已实现]` R2 保存 gzip 压缩后的 NQ 文本分页快照，不复制原始 ZIP。
- `[已实现]` NQ 图片保留原始地址并使用 `no-referrer` 页面策略。
- `[已实现]` 默认报告保留 90 天，定时任务清理 D1 和 R2。
- `[已实现]` 推广位置和当天、累计 SQ 测试次数。
- `[已实现]` GitHub 项目地址独立于推广位展示。
- `[待实测]` 桌面、窄屏和深色模式视觉检查；NQ 页面与 SQ 增补页分别检查。
- `[待决定]` 正式服务的报告保留天数、推广内容和隐私说明。
- `[未开发]` 公共节点覆盖页只展示省份、三网覆盖、IPv4/IPv6、可用档位、在线节点数量区间
  和汇总剩余额度区间，不公开 IP、端口、Node ID、Route Key 或单节点精确容量。
- `[未开发]` 运营后台展示单节点健康、版本、心跳、失败原因、并发、额度和异常趋势，并提供暂停、
  恢复、认证档位调整及凭据撤销入口；该页面必须由平台管理员认证后访问。

## 7. 防滥用和容量

- `[已实现]` 会话绑定来源 IP、地区、IP 类型、速度档位和有效期。
- `[已实现]` 每个会话限制地区数和租约重试次数。
- `[已实现]` 每来源每日会话数和报告数限制。
- `[已实现]` Worker 校验报告速率、模式、时长和结构化结果，拒绝伪造的超范围数据。
- `[已实现]` 私有 Core 按物理节点容量和并发原子预留，未反馈租约自动过期。
- `[待实测]` 真实并发下的 D1 冲突、租约释放、异常退出和节点过载表现。
- `[已实现]` 社区节点每日公共字节额度、提供者保留并发、短暂提供者优先和离线/健康熔断。
- `[待实测]` 依据真实节点负载调整默认并发、每日额度和健康检查节奏。
- `[已实现]` 在 JWT 校验前按来源 IP 限制连接和请求频率，避免无效请求消耗过多 CPU、内存
  和 goroutine。
- `[已实现]` 给整个监听端口设置硬连接上限，并分别限制激活、数据传输和其它请求数量；来源桶
  总数也有固定上限。
- `[已实现]` 节点总日流量硬上限覆盖公共任务和 Route Key 自用任务，并对活动任务预留额度。
- `[已实现]` 支持单独轮换或撤销 Route Key，不需要注销并重新注册整个节点。
- `[已实现]` 匿名 `/healthz` 只公开存活状态和协议版本；容量、流量及内部状态改由
  已认证心跳上报。
- `[待实测]` `sq-node` 已使用独立低权限系统用户运行，并配置 systemd 的内存、任务数、文件描述符、
  Linux capabilities 和地址族限制；仍需完成支持发行版矩阵验收。
- `[暂缓]` 根据异常连接率、持续拒绝和流量趋势自动判断攻击；第一版只根据明确的手工操作、
  心跳离线和健康失败暂停节点。
- `[待实测]` 公开节点已实现临时来源 IP 防火墙租约：平台下发待确认租约，受限网关把
  IPv4/IPv6 和随机端口写入带超时的 nftables 集合，节点确认后平台才返回测速租约。
- `[已实现]` 安装器只读检查 SSH 有效认证配置、nftables 可用性、测速端口范围和公网高风险
  服务；严重风险节点强制保持 `private`，修复后由提供者手动开启，程序不修改 SSH。
- `[待实测]` 云安全组、SSH 来源限制及 IPv4/IPv6 现有防火墙策略由提供者人工核对；不同发行版
  输出差异需在部署矩阵中验证。
- `[待实测]` 公共节点使用每租约随机外部端口；端口只对租约
  来源 IP 开放，释放或最长 3 分钟后自动删除。
- `[待实测]` `sq-node emergency-stop` 已串联平台暂停、租约撤销、临时端口清理和公网监听停止，
  状态跨服务与机器重启保持；恢复必须由提供者主动检查并确认。
- `[已实现]` `sq-node telemetry` 显示当前认证心跳将上报的完整字段；第一阶段只上报注册、健康、
  容量、可用状态和总流量，不上报攻击来源、其它端口事件或整机网络摘要。
- `[暂缓]` 跨节点攻击来源采集、风险画像和主动预警。只有真实运营证明其有效且节点提供者重新
  同意后再设计，不作为私有 Alpha 或公开 Beta 的发布门槛。
- `[要求]` 完整设计、隐私期限和验收标准见 [`community-node-security.md`](community-node-security.md)。
- `[外部风险]` 临时白名单可以减少端口滥用和应用层资源消耗，但无法阻止打满服务器公网入口的
  大流量攻击；该问题只能依赖服务商上游防护，或给测速服务使用可隔离、更换的独立 IP/机器。

## 8. 后续能力扩展

- `[决策]` 当前第三方兼容节点只承担现有速度测试，不展示无法由对端证实的质量指标。
- `[已实现]` 第一版只公开通用能力协商和签名更新，不预埋未使用的测量接口。
- `[规划]` 新测量能力完成内部校准后，通过带独立版本号的能力模块上线。
- `[规划]` 报告在确有第二类有效结果时才增加“连接质量”分页。
- `[说明]` 新能力通过 `sq-node` 和 `sqprobe` 签名更新上线；拒绝升级的旧节点继续只测速。
- `[私有]` 未发布能力的算法、数据结构和校准计划保存在私有运营仓库，不进入公开路线文档。

## 9. 开源边界和来源说明

公开 GitHub 仓库计划包含：

## 11. 发布门槛和顺序

### 第一阶段：可审计代码

1. 完成 Taier 署名、第三方清单和许可证检查。
2. 确定名称、域名和公开/私有仓库边界。
3. 建立 Git 提交并让全部自动化测试通过。

### 第二阶段：私有 Alpha

1. 部署 Cloudflare 资源和私有 Node Core。
2. 只使用自有节点，以 `private` 模式验证低权限服务、硬限制、一次性防火墙租约和紧急隔离。
3. 先启用少量省份、IPv4、单线程和 100/200 Mbps。
4. 完成两种出口、三网节点、429、IPv6 和流量统计实测。
5. 使用真实 NQ 报告检查联合分页；无法稳定复现时保留原报告链接回退。

### 第三阶段：公开 Beta

1. 低权限服务、硬限制、SSH 风险降级、一次性防火墙租约和 `emergency-stop` 全部通过验收。
2. 根据容量逐步开放 400 Mbps、`bsg` 和最多五省。
3. 开启基础可用性监控、节点冷却和成本统计，不启用攻击来源采集或跨节点画像。
4. 发布测速方法、结果局限、运行数据、隐私和第三方来源说明。

### 第四阶段：原生节点网络

1. `[已实现]` 开发 `sq-node`、终端菜单、注册、验证、额度和凭据。
2. `[已实现]` 完成 `--node ROUTE_KEY` 与原生节点优先调度。
3. `[待实测]` 部署首批自有节点，验证容量和公网可达性。
4. `[待运营]` 逐步提高 SQ 原生节点覆盖，最后关闭兼容回退。
