# v1.5.0 发布说明

新增固定节点名称、四家归属地交叉校验和后台节点发现，便于识别重复测速使用的节点，并减少单一归属地数据不完整造成的节点缺失。

- 节点可显示为“武汉电信1号 · 第三方”。名称与完整节点编号及 IP 类型固定对应；IPv4、IPv6 分别编号，编号不回收。名称用于辨认节点，不代表物理机位置证明，也不保证每次自动选中相同节点。
- 归属地核验接入 ipwho.is、IP.SB、IPinfo 和 IP2Location，优先城市匹配，其次省份匹配，同时检查国家和运营商。查询采用共享缓存、请求去重、访问预算和失败退避。
- 全国三网节点目录按五天一轮分散扫描；遇到服务故障或限流时顺延。扫描只更新目录和归属信息，地图点亮仍需要有效归属与近期实际测速成功记录。
- 节点选择结合预约带宽占比和最近分配时间，让可用节点轮换参与测速；近期持续失败的节点暂时避让，全部忙碌时继续使用原有排队机制。
- 终端、网页报告、复制格式、链接预览图和地图同步展示名称。历史报告只有完整节点身份准确匹配时才补充名称，保留旧客户端和旧报告兼容性。
- 不新增测速用户完整 IP 的存储，也不建立用户 IP 与固定测速节点的绑定。

IP2Location 公共查询页可能限流、要求验证或变更格式；此时标记为待核验，不把查询失败判为归属冲突。平台维护者可配置官方 API，默认不会启用付费服务。

平台升级需先备份私有 Core 数据库并应用新增迁移，再更新 Core 和公开服务，最后切换测速程序。节点名称登记及持久盐应随数据库备份保留。VPS 部署还需重新构建包含新增依赖的平台镜像。

已完成 Core、公开服务、探针、节点服务、Bash、VPS/Redis 和桌面/手机回归检查。44 份已保存节点样本回放中，31 份城市匹配、11 份省份匹配、2 份不匹配；该结果用于验证规则，不代表上游实时可用率。
