# v1.7.0 发布说明

`--sq` 现在可以复用已有的两份 SQ 联合报告。此前传入 A＋B 链接会在测速前被拒绝；现在终端
列出两份结果的完整检测时间（北京时间）、省份、速度档位和 IPv4/IPv6，用户选择保留 A 或 B，
只需再测一次 C 即可得到 A＋C 或 B＋C。选择发生在探针下载、会话及节点申请之前。

编号固定为：1 是联合报告中的历史 SQ，2 是生成该联合报告时的新测速。没有默认选择；输入
0 取消。非交互运行可用 `--sq-keep 1` 或 `--sq-keep 2` 指定，否则显示选项后停止。
只有一份 SQ 的链接继续直接关联。
等待选择时明确提示“需要手动选择：测速尚未开始，正在等待你的输入”，并在选择完成后提示开始准备测速。

新组合只引用所选的单次测速，不递归引入其旧关联，始终最多两份 SQ。原报告内容和保存期限
保持不变，每次新测速生成新链接。选中的结果单独校验出口身份；过期结果不能选择，但另一份
有效结果仍可复用。联合报告展示的 NQ 继续作为候选，重新校验身份并按距新测速时间选择。

无需数据库迁移或私有 Core 升级。生成并验证已签名的 v1.7.0 Release 后，部署新版公开 Worker，
并将 `/run` 与探针版本同步切换到 v1.7.0。旧客户端关联单份报告继续可用；遇到联合链接仍在测速前停止并提示
使用新版脚本选择。回退时恢复旧 Worker 和脚本版本，已创建的两份报告仍按原结构读取。

验证包含真实 SQLite 的 A＋B → A＋C / B＋C 与重复复用、原报告不变、身份及签名校验、
过期边界、NQ 候选，以及真实 PTY 终端选择、输入纠正、取消、自动运行和双栈出口重试。
