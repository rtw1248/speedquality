# v1.4.2 发布说明

修复测速开始较慢、节点拒绝请求或传输提前结束时，可能得到不准确低速结果的问题。

- 每个方向从首次传输数据开始预热约 2 秒，再完整测量 5 秒；连接和首数据等待单独计时，最多等待 10 秒。此前等待过久可能占用正式测量时间，拉低吞吐均值。
- HTTP 非 2xx、响应提前结束或连接中断时，该方向显示“失败”，不再把短响应或中断后的平均值当作有效速率；另一方向的有效结果仍然保留。
- 每个方向继续使用单个请求、单条连接，测速请求不跟随重定向。正常完成的低速结果按实测值保留，不通过重试挑选更高数值。
- 可选诊断日志增加连接及首数据等待、正式测量耗时和归类后的失败原因，不新增完整 IP、请求地址或凭据记录。
- 补充前置机与专线的测量说明：SQ 遵循运行机器的系统路由，入口端口转发不代表主动出站连接也经过专线。
- 纳入已上线的论坛复制菜单：NodeSeek、烧饼论坛使用兼容格式，IDCFlare 使用标准 Markdown。

现有命令和结果 JSON 字段保持兼容，无需数据库迁移。上传字节仍以交给 HTTP 传输层的请求体为准，传输缓冲可能带来误差。

已通过测速探针回归与竞态检查、Shell 与节点服务测试、报告兼容检查，以及 Linux amd64/arm64 构建。本地模拟中，首数据延迟 4 秒的 200Mbps 数据流由约 121.62Mbps 修正为约 199.96Mbps；该结果用于验证计时修复，不代表公网线路表现。
